# 16: Кредитийн хугацаа дуусалт

**What to build:** Хугацаа нь дууссан кредит lot өдөр бүрийн ажлаар `expire` бичилтээр хасагдана. Хугацаа дуусахаас 30 болон 7 хоногийн өмнө хэрэглэгч сануулга авна.

**Blocked by:** 03, 08

**Status:** done — production-д Redis дээр cron бодитоор ажиллаж байгааг шалгах үлдсэн (доорх "Үлдсэн")

> Шийдвэр: Нэг өдөр тутмын ажил `credits.expiry` (`10 0 * * *`, Улаанбаатар) — `CreditExpiryService` (`apps/api/src/credits/expiry.service.ts`). Эхлээд дуусгавар, дараа нь сануулга. Тестэд `t.queue.runScheduled(CREDIT_EXPIRY_JOB)` эсвэл цаг шилжүүлэхэд `CreditExpiryService.run(now)`.
>
> Шийдвэр: Дуусгавар нь 08-ын `CreditsService.expireDue`-г ашиглана; шинэ `expireDueLots(now, batchSize)` нь мөн логик боловч **энэ дуудлага** дуусгасан lot-уудыг буцаана (мэдэгдэлд). `expireDue` = `expireDueLots(...).length` — гарын үсэг, утга өөрчлөгдөөгүй. Lot бүр тусдаа transaction-д хэрэглэгчийн мөрийн түгжээ дор дахин уншиж, `expiredAt IS NULL AND remaining = <уншсан>` нөхцөлт update хийнэ → зэрэг cron давхар хасахгүй, `spend()`-тэй зэрэг ажиллахад аль нэг нь дараалж (spend түрүүлбэл үлдсэнийг нь, expire түрүүлбэл spend 0 үлдэгдэл харна). Cron batch (500)-аар хоосортол давтана.
>
> Шийдвэр: Баланс/`spend()` нь `expiresAt > now`-оор шүүдэг (08) тул cron ажиллахаас өмнө ч дууссан lot зарцуулагдахгүй, баланст орохгүй. Тэр завсарт л ledger нийлбэр > баланс байж болно; cron EXPIRE бичсэнээр тэнцэнэ.
>
> Шийдвэр: Сануулга — `credit_lots.remind_30_sent_at`, `remind_7_sent_at` (migration `20261117710000_credit_expiry`). Босго бүрийг lot тус бүрээр нөхцөлт `updateMany` (`… IS NULL`)-ээр "claim" хийнэ — мөр бүр тусдаа statement тул `spend()`-ийн lot түгжээтэй deadlock үүсэхгүй, зэрэг ажилд нэг л ажил авна. Нөхцөл: `expiredAt IS NULL`, `remaining > 0`, `now < expiresAt ≤ now + N хоног`. 7 хоногийнхыг авсан lot 30 хоногийнхыг хэзээ ч авахгүй (хоцорсон/богино lot-д хоёр сануулга нэг дор очихгүй). 30 хоногийн сануулгын дараа бүгдийг зарцуулбал 7 хоногийнх очихгүй.
>
> Шийдвэр: Нэгтгэл — нэг ажилд хэрэглэгч бүрт дээд тал нь нэг `CREDITS_EXPIRING` мэдэгдэл (энэ ажилд claim хийсэн lot-уудын нийт үлдэгдэл, хамгийн эрт дуусах огноо `YYYY-MM-DD` Улаанбаатар, үлдсэн хоног) ба нэг `CREDITS_EXPIRED` (энэ ажил хассан нийт кредит). In-app + имэйл (`notify()`), link `/credits`. Зэрэг хоёр ажил нэг хэрэглэгчийн lot-уудыг хуваан авбал хоёр хэсэгчилсэн мэдэгдэл очиж болно — кредит давхар тоологдохгүй (тестээр баталсан).
>
> Шийдвэр: Мэдэгдэл claim / EXPIRE commit хийсний **дараа** илгээгдэнэ → дээд тал нь нэг удаа (process яг тэр завсарт унавал тухайн сануулга алдагдана, давхардахгүй). Нэг хэрэглэгчийн `notify` алдаа бусдыг зогсоохгүй (log).
>
> Шийдвэр: Тест (`isTest`) lot-д ч сануулга/дуусгаврын мэдэгдэл очно — тест багцыг зөвхөн админ авдаг тул бүх урсгалыг production-д шалгахад хэрэгтэй. EXPIRE бичилт нь lot-ын `isTest`-ийг авна (08).
>
> Шийдвэр: `/credits` хуудсанд 30-аас цөөн хоног үлдсэн lot-ыг улаан хүрээ + "N хоногийн дараа дуусна", дээр нь нэг анхааруулга мөр.
